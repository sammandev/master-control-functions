# Troubleshooting Playbook & AI Knowledge Base Design

## Intent & Why

Provide test engineers and production operators with a step-by-step Troubleshooting Playbook during DUT testing and production runs, while capturing engineer-authored troubleshooting guides in a structured database schema and read-only `mcp_v1_*` views so AI assistants can consume them as diagnostic context for test program errors, DUT issues, and production issues.

Because a single problem, symptom, or `ERRCODE` can manifest in multiple ways across different DUTs, stations, or script bundles, **each problem or error code may have multiple distinct guides/solutions**. Guides are therefore not constrained to a 1:1 mapping with an error code or problem title; instead, multiple guides can share the same `error_code`, `problem_code`, `function_name`, or `device_name`, and the UI surfaces related solutions side-by-side when viewing any guide that shares an error code or problem group.

## Goals

- Add a web-native PostgreSQL schema (`0009_troubleshooting.sql`) for `troubleshooting_guides` and `troubleshooting_steps`, plus read-only AI/MCP views (`mcp_v1_troubleshooting_guides`, `mcp_v1_troubleshooting_steps`).
- Support multiple guides/solutions per problem or error code (`error_code`, `function_name`, `device_name` are non-unique filterable/groupable tags; each guide has its own descriptive `title`, `symptom`, `root_cause`, and ordered `steps`).
- Provide a REST CRUD API at `/api/troubleshooting` (`GET`, `POST`, `GET /:id`, `PUT /:id`, `DELETE /:id`) with filtering by `search`, `category`, `device_name`, and `error_code`.
- Build an Approach A Master-Detail Playbook workspace at `/troubleshooting` following Shadcn Svelte and Bits UI conventions:
  - Left rail: Search input (`title`, `symptom`, `error_code`, `function_name`, `root_cause`), Category `Select`, Device `DevicePicker`, Error Code quick-filter badge, and selectable guide items showing how many solutions match.
  - Right detail pane: Problem & Error Code header badges, sibling/alternative solution switcher when multiple guides address the same `error_code` or `function_name`, Symptom & Root Cause cards, interactive Step-by-Step Resolution Checklist (`Checkbox`, progress counter, copyable script snippet, verification block), and a **"Copy AI Context"** action (copies structured Markdown/JSON for AI prompts).
  - Effortless Creation & Cloning: Guided `TroubleshootingDialog.svelte` with a **"Add Another Solution for This Error/Problem"** button that pre-fills `category`, `device_name`, `function_name`, and `error_code` so engineers can quickly document an alternate manifestation or fix.

## Non-Goals

- Modifying the 6-sheet Excel workbook import/export contract (troubleshooting guides are web-native like `sequences` and `function_grammars`).
- Running database operations against the approved Ubuntu production host from the agent environment.

## Constraints

- Strict adherence to Shadcn Svelte and Bits UI primitives in `frontend/src/lib/components/ui/*` and semantic theme tokens (`bg-card`, `bg-popover`, `border-border`, `text-foreground`, `text-muted-foreground`, `focus-visible:ring-ring`).
- Device names normalized with `normalizeDeviceName` / `validateDeviceName` (trimmed, uppercase; `""` means Global).
- Every guide requires a non-empty `title`, valid `category` (`connection` | `execution` | `measurement` | `production`), valid `severity` (`critical` | `warning` | `info`), non-empty `symptom`, and at least one resolution step (`title` and `instruction` required).

## Approaches Considered

1. **Full-Stack Web-Native Table + Multi-Solution Grouping + MCP Views + Approach A Master-Detail UI (Selected)**: Stores guides and ordered steps in PostgreSQL, exposes `/api/troubleshooting`, provides `mcp_v1_*` read-only views for AI tools, and renders an interactive step checklist with multi-solution switching and guided creation in SvelteKit.
2. **Frontend-Only `localStorage` Playbook**: Zero backend code, but engineer-created guides aren't shared across stations or queryable via SQL/MCP views.

## Technical Design

### 1. Database Schema (`backend/internal/db/postgres_migrations/0009_troubleshooting.sql`)
- `troubleshooting_guides`:
  - `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
  - `title TEXT NOT NULL` (specific solution/manifestation title, e.g., `"SSH Prompt Timeout Due to RD_SETTING Prompt Mismatch"`)
  - `category TEXT NOT NULL CHECK (category IN ('connection', 'execution', 'measurement', 'production'))`
  - `severity TEXT NOT NULL CHECK (severity IN ('critical', 'warning', 'info'))`
  - `device_name TEXT NOT NULL DEFAULT ''`
  - `function_name TEXT NOT NULL DEFAULT ''`
  - `error_code TEXT NOT NULL DEFAULT ''` (e.g., `ERRCODE:101`, `*V:Section-Key#`, `TX_POW_FAIL` — non-unique so one error code can have many guides/solutions)
  - `symptom TEXT NOT NULL DEFAULT ''`
  - `root_cause TEXT NOT NULL DEFAULT ''`
  - `created_at TEXT NOT NULL`
  - `updated_at TEXT NOT NULL`
- `troubleshooting_steps`:
  - `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
  - `guide_id BIGINT NOT NULL REFERENCES troubleshooting_guides (id) ON DELETE CASCADE`
  - `position BIGINT NOT NULL`
  - `title TEXT NOT NULL`
  - `instruction TEXT NOT NULL`
  - `script_snippet TEXT NOT NULL DEFAULT ''`
  - `verification TEXT NOT NULL DEFAULT ''`
- Pre-seeded with realistic MCV2 guides, including multiple distinct guides/solutions for the same error code / problem (e.g., two different causes/solutions for `ERRCODE:104` / `TX_MULTI_VERIFICATION` power failure: one for `TX_TARGET_POWER` vs tolerance arithmetic in `TEST_SPEC.ini`, and one for RF path-loss table mismatch in `RD_SETTING.ini`).
- Views:
  - `mcp_v1_troubleshooting_guides`
  - `mcp_v1_troubleshooting_steps`

### 2. Backend API (`backend/internal/api/troubleshooting.go`)
- `GET /api/troubleshooting`: returns `{ items, total, page, page_size }` filtered by optional `search`, `category`, `device`, `error_code`.
- `GET /api/troubleshooting/:id`: returns the guide with its ordered `steps`.
- `POST /api/troubleshooting`: validates and inserts a guide + ordered steps in a transaction.
- `PUT /api/troubleshooting/:id`: validates and full-replaces metadata + ordered steps in a transaction.
- `DELETE /api/troubleshooting/:id`: deletes the guide (cascading steps).

### 3. Frontend Workspace (`frontend/src/routes/troubleshooting/+page.svelte` & Components)
- Navigation entry `{ href: '/troubleshooting', label: 'Troubleshooting' }` in `frontend/src/routes/+layout.svelte`.
- Typed client in `frontend/src/lib/troubleshooting.ts` with an offline/demo fallback seed if the backend is unreachable during static UI preview.
- Master-Detail split pane:
  - Left sidebar: Search input, Category `Select`, Device `DevicePicker`, Error Code filter pill, and guide list items showing title, device/error-code badges, step count, and a badge when multiple solutions exist for that error code.
  - Right detail pane:
    - Header with `Badge`s (`category`, `severity`, `device_name || 'Global'`, `error_code`, `function_name`).
    - **"Other Solutions for This Problem / Error Code"** banner when >1 guide shares the same `error_code` or `function_name`, allowing 1-click switching between alternative solutions and a **"+ Add Alternate Solution"** button.
    - Symptom & Root Cause cards.
    - Interactive Step-by-Step checklist (`Checkbox`, step progress bar/badge, copyable script block, expected verification, reset button).
    - **"Copy AI Context"** button producing structured Markdown/JSON ready for AI troubleshooting assistants.

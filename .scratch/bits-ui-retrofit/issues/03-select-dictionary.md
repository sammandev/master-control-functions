## Comments

- **Coverage: 15 dropdown sites**, not the 13 implied by the ticket list — the functions dialog's Source field (`f-source`), the examples dialog's Function source field (`example-source`), and LinksPanel's inline create-definition Type field (`inline-type`) are dropdowns too and the AC says no native `<select>` remains, so they migrated as well. Total: functions 7 (5 facets + page-size + f-source), DictionaryPage 3 (type + cardinality + page-size), orphans 2, LinksPanel 1, ComposeDialog 1 (seq target), ExamplesPanel 1.
- **bits-ui 2.19 Select facts** (differ from the old native select): the Trigger is a plain `<button aria-haspopup="listbox">` — no combobox role — so e2e uses `getByRole('button', { name })`; `value: ''` means "no value" (placeholder shows, data-placeholder set) but is still a selectable item value, so the "All …" facet options pair `value: ''` with `placeholder="All …"`; a button's accessible name is its content, which beats `label[for]`, so every labeled dialog select passes an explicit `ariaLabel` mirroring the visible label; the listbox portals to the document body — a sibling of a portaled dialog, not a descendant — so e2e looks options up at page level; opening highlights the selected item, and focus stays on the trigger (aria-activedescendant), so pure `page.keyboard` flows work.
- **Wrapper API**: `ui/select.svelte` is generic over the value's string union (`V extends string`) so typed fields like `cardinality: 'SINGLE' | 'MULTIPLE'` bind without casts; sites control the value with `bind:value` or `value` + `onchange`; options are also handed to bits-ui's `items` for trigger typeahead and selected-label resolution. One sound internal assertion (`v as V`) bridges bits-ui's string onValueChange to the site's union.
- **Checkbox wrapper bug fixed en route**: its first-ever mount (dictionary dialog) hit "Maximum call stack size exceeded" — the wrapper destructured a caller `children` prop and also declared an internal `{#snippet children}` that referenced it, recursing at render.
